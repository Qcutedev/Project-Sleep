# สถานะงานและปัญหาที่รู้อยู่

ไฟล์นี้บอกว่าอะไรค้างอยู่ อะไรรู้ว่ามีปัญหาแต่ยังไม่แก้ และอะไรที่ยังไม่มีข้อมูล อัปเดตทุกครั้งที่ปิดงานหรือเจอปัญหาใหม่ (อัปเดตล่าสุด: 2 พ.ย. 2026)

## ยังไม่ได้ยืนยันบนมือถือจริง

งานพวกนี้เขียนโค้ดและผ่าน `flutter analyze` แล้ว แต่ยังไม่มีใครยืนยันผลบนเครื่อง ถ้าเจ้าของโปรเจคพูดถึง ให้ถามผลก่อน อย่าสมมติว่าใช้ได้

| เรื่อง | รายละเอียด |
|---|---|
| ปุ่ม "ตั้งปลุก" เคยค้างไม่กลับหน้ารายการ | แก้โดยครอบการตั้งปลุกด้วย try/timeout แล้วกลับหน้ารายการเสมอ แต่ **ยังไม่รู้สาเหตุจริง** ที่ทำให้ค้าง สงสัยว่าเป็นสิทธิ์ปลุกตรงเวลาของ Android |
| หน้ารายการปลุกเคยหมุนค้าง | แก้โดยแสดงรายการจากที่เก็บในเครื่องก่อน แล้วค่อยตั้งปลุกจริงเบื้องหลัง |
| แจ้งเตือน "ตั้งปลุกแล้ว" ไม่ขึ้นใน APK แบบ release | สาเหตุ: ไอคอน `ic_stat_notification` ถูกตัดทิ้งตอน build แบบ release เพราะถูกเรียกด้วยชื่อจาก Dart เท่านั้น ยืนยันแล้วจากตารางทรัพยากรใน APK แก้โดยเพิ่ม `android/app/src/main/res/raw/keep.xml` และให้ถอยไปใช้ไอคอนแอปถ้าไอคอนเฉพาะใช้ไม่ได้ **ยังรอเจ้าของโปรเจคยืนยันบนเครื่อง** |
| คำแนะนำตามคะแนน (หน้า Result), คำแนะนำระยะยาว (หน้า Stats) และสไลเดอร์นอนสูงสุด 10 ชม. | เรนเดอร์ในเทสต์แล้ว ไม่ล้นกรอบทั้งสองภาษาที่กว้าง 320/360 แต่ยังไม่เคยดูบนเครื่องจริง และ**เกณฑ์/ถ้อยคำของคำแนะนำเป็นร่างของ Claude** เจ้าของโปรเจคยังไม่ได้ตรวจ |
| การแตะจุดบนกราฟในหน้า Stats เพื่อดูค่า | ยังไม่เคยลองแตะจริง |
| คำแนะนำสิทธิ์ของ Xiaomi และปุ่มเปิดการตั้งค่า | ยังไม่รู้ว่าเปิดหน้าสิทธิ์ของ MIUI ได้ถูกหน้าหรือไม่ |
| รีเซ็ตข้อมูลแล้วยกเลิกปลุกจริง | อ่านจากโค้ดแล้วเจอว่าเดิมไม่ยกเลิก แก้แล้วแต่ยังไม่เคยลองตั้งปลุก รีเซ็ต แล้วรอดูว่าไม่ดัง |
| เลื่อนปลุกตามค่าที่ตั้ง | เทสต์การหาปลุกต้นทางแล้ว แต่ยังไม่เคยลองตอนปลุกดังจริง |
| ข้อความ error, ข้อความรอเซิร์ฟเวอร์ และ `warmUp()` | เทสต์ประเภทความผิดพลาดและเรนเดอร์หน้า error แล้ว แต่ยังไม่เคยลองปิดเน็ตบนเครื่องจริง |
| หน้าแนะนำแอป, กรอกเวลาเข้านอน/ตื่น, เป้าหมายการนอน และสรุปรายสัปดาห์ | เรนเดอร์ในเทสต์แล้ว ไม่ล้นกรอบทั้งสองภาษาที่กว้าง 320/360 ยังไม่เคยลองบนเครื่อง และถ้อยคำเป็นร่างของ Claude |
| ส่งออกประวัติเป็น CSV | เทสต์การสร้างไฟล์แล้ว แต่กล่องบันทึกไฟล์ของระบบยังไม่เคยลอง |
| label ของโปรแกรมอ่านหน้าจอ | เทสต์ label ของกราฟและคะแนนแล้ว ยังไม่เคยลองกับ TalkBack |
| ชื่อแอป, package ใหม่, กุญแจเซ็น, Splash 2 วินาที และสีพื้นตอนเปิดแอป | ตรวจ APK ด้วยเครื่องมือแล้ว ยังไม่เคยติดตั้งบนเครื่องจริง |

## พักไว้ตามที่เจ้าของโปรเจคตัดสินใจ

- **ชื่อ `kiwnoz` และ commit ภาษาไทยใน history** ปล่อยไว้ ดู [GITHUB.md](GITHUB.md)

## ปัญหาที่รู้อยู่และยังไม่แก้

ไม่มีข้อไหนทำให้แอปใช้งานไม่ได้ แก้เมื่อถูกขอ หรือเสนอเมื่อไปแตะไฟล์นั้นอยู่แล้ว

| ปัญหา | ที่ไหน |
|---|---|
| AM/PM ในหน้าเลือกเวลาปลุกยังเป็นอังกฤษ | ต้องเพิ่ม `flutter_localizations` ถ้าจะแก้ |
| Render แผนฟรีทำให้เซิร์ฟเวอร์เริ่มช้า 30–60 วินาที | `warmUp()` ช่วยลดโอกาสรอ แต่ยังรอได้ถ้าผู้ใช้กดวิเคราะห์ทันทีหลังเปิดแอป |
| iOS / เว็บ / เดสก์ท็อป ไม่เคยตั้งค่าหรือทดสอบ และยังใช้ชื่อ `com.example` | ใช้งานจริงแค่ Android |
| โมเดลให้คะแนนเท่ากันเมื่อนอน 0–5 ชม. และกิจกรรมทางกายแทบไม่มีผล | ข้อจำกัดของโมเดล ดู [MODEL_CARD.md](MODEL_CARD.md) แก้ได้ด้วยการเทรนใหม่เท่านั้น |
| `ListTile` ในหน้า Settings อยู่ใน `Container` ที่มีสีพื้น จึงขึ้นคำเตือนใน debug ว่าอาจไม่เห็น ink ตอนแตะ | `_card` ใน `settings_screen.dart` |
| มาสคอตอิงจาก Cinnamoroll ของ Sanrio | ถ้าจะเผยแพร่สู่สาธารณะควรออกแบบตัวละครของตัวเอง เจ้าของโปรเจคเป็นคนเลือกตัวนี้ จึงยังไม่เปลี่ยน |
| ไฟล์เสียงใน `assets/sounds` ไม่มีที่มาหรือสัญญาอนุญาต | ต้องได้ที่มาจากเจ้าของโปรเจคก่อนจึงจะทำหน้า credits ได้ |
| ไฟล์เสียงรวม 26 MB (256 kbps) | ยังไม่บีบ เพราะเป็นการลดคุณภาพแบบย้อนไม่ได้ อาจทำให้รอยต่อตอนวนซ้ำเปลี่ยน และต้องลองฟังบนเครื่อง |

## ข้อมูลที่ยังไม่มีในเอกสาร

เรื่องพวกนี้ไม่อยู่ในโค้ด ต้องถามเจ้าของโปรเจคก่อนทำงานที่เกี่ยวข้อง ห้ามเดา

- **การ deploy backend บน Render**: deploy จาก branch ไหน, deploy อัตโนมัติเมื่อ push หรือกดเอง, ตั้งค่า root directory และคำสั่ง start ว่าอะไร ต้องรู้ก่อนแก้อะไรใน `backend/`
- **โมเดล**: dataset ที่ใช้เทรน, ใครเทรน, โค้ดเทรนอยู่ที่ไหน, ความแม่นยำ ต้องรู้ก่อนเสนอเพิ่มหรือเปลี่ยนค่าที่ส่งให้โมเดล สิ่งที่วัดจากไฟล์ได้แล้วอยู่ใน [MODEL_CARD.md](MODEL_CARD.md)
- **เวอร์ชัน Python บน Render**: ยังไม่ได้ระบุไว้ใน repo เพราะไม่รู้ค่าที่ใช้จริง และการเพิ่มไฟล์กำหนดเวอร์ชันอาจกระทบการ deploy
- **เอกสาร "project context" ของรายวิชา CPE310**: คอมเมนต์ในโค้ดอ้างถึง "ข้อ 15 (Healthcare Disclaimer)" แต่ตัวเอกสารไม่อยู่ใน repo ข้อกำหนดข้ออื่นจึงไม่ทราบ
- **กำหนดส่งและขอบเขตงานที่ต้องส่ง**
- **มีสมาชิกทีมคนอื่นทำงานใน repo นี้ด้วยหรือไม่** (มี branch `feature/api-model-integration` และผู้ร่วมพัฒนาชื่อ `sutlyxz` บน GitHub)
