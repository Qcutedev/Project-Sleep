# แนวทางการเขียนโค้ดและ UI

อ่านไฟล์นี้ก่อนแก้หน้าจอ เพิ่มข้อความ หรือเพิ่มหน้าใหม่

## ระบบสองภาษา (อังกฤษ / ไทย)

ข้อความทั้งหมดอยู่ที่ `lib/l10n/app_strings.dart` ในคลาส `S` ไม่ได้ใช้ `flutter_localizations` หรือไฟล์ `.arb`

### เพิ่มข้อความใหม่

```dart
// ใน class S
String get myLabel => _t('English text', 'ข้อความไทย');
String itemsCount(int n) => _t('$n items', '$n รายการ');
```

### เรียกใช้

| ที่ไหน | ใช้ | เหตุผล |
|---|---|---|
| ใน `build()` หรือเมธอดที่มี `context` | `S.of(context)` | ลงทะเบียนให้หน้านั้น rebuild เมื่อสลับภาษา |
| นอก widget tree (model, service, callback async, dialog builder) | `S.current` | ไม่มี context ที่เหมาะจะผูก |

หน้าที่อ่านข้อความผ่าน `S.current` อย่างเดียว ต้องมี `S.of(context)` อย่างน้อยหนึ่งครั้งใน `build()` ไม่อย่างนั้นสลับภาษาแล้วหน้านั้นจะไม่เปลี่ยน (ดูตัวอย่างใน `sounds_screen.dart`)

### กติกา

- **ห้ามเขียนข้อความที่ผู้ใช้เห็นตรงๆ ในหน้าจอ** รวมถึง snackbar, dialog, tooltip, hint, ข้อความใน notification
- ข้อความไทยต้อง **สั้นพอๆ กับอังกฤษ** ถ้าแปลตรงตัวแล้วยาว ให้เลือกคำที่สั้นกว่า
- ไม่แปล: ชื่อแอป "SleepWise AI", "CPE310", ชื่อภาษาในตัวเลือกภาษา ("ไทย" / "English" แสดงแบบนี้เสมอ)
- ค่าที่เป็นข้อมูล ไม่ใช่ข้อความ ห้ามแปล: `Good`/`Fair`/`Poor`, `Male`/`Female`, key ต่างๆ ให้แปลตอนแสดงผลด้วย `s.quality(raw)`, `s.factor(raw)`, `s.recommendation(raw)`
- ข้อความใน notification ถูกกำหนดตอนตั้งเวลา ถ้าเพิ่ม notification ใหม่ที่ตั้งล่วงหน้า ต้องตั้งใหม่เมื่อสลับภาษา (ดู `_changeLanguage` ใน `settings_screen.dart`)
- ตัวย่อวันภาษาไทยคือ `จ อ พ พฤ ศ ส อา` ใช้ `s.dayNamesShort` / `s.dayLetters`
- ส่วนที่ยังเป็นอังกฤษโดยรู้ตัว: AM/PM ในหน้าเลือกเวลาปลุก

## ดีไซน์

แอปใช้โทนม่วง-อินดิโก สีและธีมทั้งหมดอยู่ที่ `lib/theme/app_theme.dart`

### สี

- ใช้ตัวช่วยที่รับ `context` เสมอ เพื่อให้โหมดมืดถูกต้อง: `AppTheme.bg`, `surfaceColor`, `surfaceMutedColor`, `textPrimaryColor`, `textSecondaryColor`, `textMutedColor`, `borderColor`, `warningBgColor`, `warningTextColor`
- ห้ามใช้ค่าคงที่อย่าง `AppTheme.textPrimary` หรือ `AppTheme.surface` ตรงๆ ในหน้าใหม่ เพราะจะผิดในโหมดมืด (`about_screen.dart` ยังเป็นแบบเก่า)
- สีตามคุณภาพการนอน: `AppTheme.qualityColor(raw)` และ `qualityBgColor(raw)` (เขียว / เหลืองน้ำตาล / แดง)
- สีเน้น: `AppTheme.primary` ในโหมดมืดข้อความหรือไอคอนสีม่วงบนพื้นเข้มใช้ `AppTheme.accent`

### ชิ้นส่วนมาตรฐาน

หน้า Alarm, Sounds, Result และ Stats ใช้ชุดเดียวกัน หน้าใหม่ให้ตามนี้

| ชิ้นส่วน | สเปก |
|---|---|
| การ์ดหัว | มุมโค้ง 28, ไล่สี `primary` alpha 0.95 → 0.65 จากซ้ายบนไปขวาล่าง, เงา `primary` alpha 0.25 blur 24 offset (0,12), ตัวอักษรขาว, หัวข้อ 18–19 หนา 700 |
| การ์ดเนื้อหา | พื้น `surfaceColor`, มุมโค้ง 20, padding 18, เงาดำ alpha 0.03 blur 10 offset (0,4) |
| หัวข้อในการ์ด | ขนาด 15 หนา 700 สี `textPrimaryColor` |
| กล่องไอคอน | padding 8, มุมโค้ง 10, พื้น `primaryLight` (โหมดมืดใช้ `primary` alpha 0.18), ไอคอนขนาด 18 |
| แท็บตัวเลือกหลัก | กล่อง `surfaceColor` มุมโค้ง 16 padding 5, ปุ่มที่เลือกพื้น `primary` มุมโค้ง 12 มีเงา |
| ตัวสลับเล็ก | กล่อง `surfaceMutedColor` มุมโค้ง 10 padding 3, ปุ่มที่เลือกพื้น `primary` มุมโค้ง 8, ตัวอักษร 11 หนา 600 |
| ปุ่มหลัก | สูง 56, มุมโค้ง 16, ไล่สี `primary` → `primary` alpha 0.75, เงา `primary` alpha 0.35, ตัวอักษรขาว 16 หนา 700 |
| กล่องคำเตือน | พื้น `warningBgColor`, มุมโค้ง 14, ไอคอน `warning_amber_rounded` ขนาด 16, ตัวอักษร 12 |
| ระยะขอบหน้า | `ListView` padding `fromLTRB(20, 12, 20, 24)` หรือใกล้เคียง, ระยะห่างระหว่างการ์ด 16 |

หน้า Home ต่างออกไปเล็กน้อยโดยตั้งใจ (หัวสีทึบเต็มความกว้าง มุมล่างโค้ง 28) ไม่ต้องแก้ให้เหมือนหน้าอื่น

ถ้ามีชิ้นส่วนที่ทำซ้ำอยู่แล้วให้ใช้ของเดิม: `QualityBadge`, `StatChip`, `SleepTrendChart`

## กันข้อความล้นกรอบ

เจ้าของโปรเจคให้ความสำคัญกับเรื่องนี้มาก ข้อความไทยและจอเล็ก (กว้าง 320–360) ต้องไม่ล้น

- **หน้าที่มีเนื้อหาหลายส่วนต้องเลื่อนได้** ใช้ `ListView` ห้ามใช้ `Column` + `Spacer` แบบความสูงตายตัว (หน้า Result เคยล้นเพราะแบบนี้)
- **ข้อความใน `Row` ต้องยืดหยุ่น** ห่อด้วย `Expanded` หรือ `Flexible` ยกเว้นข้อความสั้นที่ความยาวคงที่จริงๆ เช่น ตัวเลข
- **ข้อความที่ต้องอยู่บรรทัดเดียว** เลือกอย่างใดอย่างหนึ่ง:
  - `FittedBox(fit: BoxFit.scaleDown)` เมื่อไม่อยากให้ถูกตัด (หัวข้อ, ป้ายในแท็บ)
  - `maxLines: 1` + `TextOverflow.ellipsis` เมื่อตัดได้ (ป้ายรอง, ชื่อไฟล์)
- **หลายคอลัมน์เท่ากัน** ใช้ `Expanded` ทุกคอลัมน์ ไม่ใช้ความกว้างตายตัว
- อย่ากำหนดความสูงตายตัวให้กล่องที่มีข้อความหลายบรรทัด

หลังแก้ UI ให้ตรวจด้วยการเรนเดอร์จริงตามวิธีใน [BUILD.md](BUILD.md) ทั้งสองภาษา

## ถ้อยคำด้านสุขภาพ

แอปเป็นต้นแบบเพื่อการศึกษา ต้องไม่สื่อว่าเป็นการวินิจฉัย

- ใช้: "การทำนายของโมเดล", "ปัจจัยที่เกี่ยวข้องกับผลลัพธ์", "สัมพันธ์กับ", "คำแนะนำทั่วไป"
- ห้ามใช้: "วินิจฉัย" (ยกเว้นในประโยคปฏิเสธ), "สาเหตุ", "ทำให้เกิด", "รักษา", คำที่บอกว่าผู้ใช้เป็นโรค
- หน้าที่แสดงผลการทำนายหรือสถิติเชิงเปรียบเทียบ ต้องมี disclaimer กำกับ
- ตัวเลขเปรียบเทียบจากข้อมูลผู้ใช้ ต้องมีข้อมูลขั้นต่ำก่อนแสดง (ในหน้า Stats ใช้อย่างน้อย 3 ครั้งต่อกลุ่ม) เพื่อไม่ให้ตัวเลขจากข้อมูลน้อยๆ ชวนเข้าใจผิด

## โค้ด

- **คอมเมนต์เป็นภาษาไทย** ตามของเดิมในโปรเจค อธิบายเหตุผลหรือข้อจำกัดที่อ่านจากโค้ดไม่ออก ไม่ต้องอธิบายสิ่งที่โค้ดบอกอยู่แล้ว
- **State**: ใช้ `StatefulWidget` + `setState`, `ValueNotifier`, `ChangeNotifier` ไม่มี Provider / Riverpod / Bloc อย่าเพิ่มโดยไม่ถาม
- **ไม่เพิ่มแพ็กเกจใหม่โดยไม่ถามเจ้าของโปรเจค**
- **ตรรกะที่ไม่ใช่ UI** (คำนวณสถิติ, จัดกลุ่มข้อมูล) ใส่ใน `lib/services/` หรือ `lib/models/` ไม่ฝังในหน้าจอ
- **งานที่เรียกระบบของเครื่อง** (ตั้งปลุก, notification, สิทธิ์) ห้ามให้ UI รอแบบไม่มีทางออก ครอบด้วย `try/catch` และ `.timeout(...)` แล้วให้หน้าจอไปต่อได้ เคยมีปัญหาปุ่ม "ตั้งปลุก" ค้างและหน้ารายการปลุกหมุนไม่หยุดเพราะรอขั้นตอนพวกนี้
- **หลัง `await` ต้องเช็ก `mounted`** ก่อนใช้ `context` หรือ `setState`
- รัน `flutter analyze` ให้ผ่านโดยไม่มี issue ก่อนถือว่างานเสร็จ
